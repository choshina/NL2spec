# Benchmarks: the 145 repair instances

This directory holds the datasets of the ReSTLess evaluation (paper, Section 7). An instance

`I_i = (r_i, φ*_i, S_i, C_i, φ0_i)`

contains a natural-language requirement, a reference STL formula, a signal interface, trace constraints (horizon, time step, and `H_inf`), and an initial formula generated by GPT-5.6. Under the frozen bounded evaluation semantics, the generated formula `φ0` is semantically different from the reference `φ*` but repairable within the edit scope evaluated in the paper.

| Dataset | Directory | Instances | Origin of the requirements | Initial formula φ0 |
|---|---|---|---|---|
| ARCH-COMP | `Archcomp/` | 12 | Properties of the falsification benchmarks (AFC, CC, F16, NN, PM, SB, SC); requirement texts were written by engineers | GPT-5.6 translation under an underspecified prompt |
| DeepSTL | `DeepSTL/` | 123 | 122 retained instances from synthetic DeepSTL requirements plus one NASA FRET LPC instance, reported together as DeepSTL | GPT-5.6 translation under an underspecified prompt |
| STDP | `STDP/` | 10 | STL task specifications from `bfz111/STDP-Dataset`; requirement texts were written by engineers | GPT-5.6 translation under an underspecified prompt |
| **Total** | | **145** | | |

In the submitted paper, the RQ1 phrase **DeepSTL-based benchmark** and the
`DeepSTL` column both denote this combined DeepSTL reporting group. They include
the single NASA FRET LPC instance; LPC is an upstream source, not a fourth
reported dataset, result column, or experiment tag. Accordingly, the reported
500 generated formulas consist of 499 DeepSTL-derived candidates and one LPC
candidate, and the 123 retained instances consist of 122 and one, respectively.

The 145 instances are derived from 108 **source-requirement groups** and are exactly the repair set listed in `results/final_145/final_145_ids.csv`. A source requirement may contribute multiple natural-language/prompt variants; these variants share one `requirement_id`. Statistical analyses cluster instances by that source-requirement ID rather than treating the variants as independent observations. All methods start from the same frozen `φ0` for an instance.

## Provenance of the formulas

### Reference formulas and requirements

The reference formula `φ*` and requirement `r` precede formula generation and come from four complementary sources:

- **DeepSTL** supplies synthetic natural-language requirements paired with STL ground truth and accounts for most of the evaluation set.
- **NASA FRET LPC** contributes one requirement and reference formula. It is included in the DeepSTL count in tables and plots.
- **ARCH-COMP** contributes reference properties from the competition's automotive and aerospace falsification benchmarks. Engineers wrote the corresponding English requirements.
- **STDP** contributes the STL task specifications released with the Signal Temporal Logic-guided Diffusion Policy for UAV visual navigation (`bfz111/STDP-Dataset`). Engineers wrote the corresponding English requirements.

### DeepSTL source sampling

The DeepSTL requirements were drawn from the public DeepSTL corpus using a
fixed, stratified sampling protocol. Before sampling, formulas containing the
non-standard temporal extensions `rise`, `fall`, `historically`, `once`,
`since`, or `previously` were excluded, and the remaining formulas were
normalized to the STL notation used in this artifact. Sampling used seed 42
and selected 125 source items from each of the four native DeepSTL types:
`temporal_response`, `stabilization_recurrence`, `immediate_response`, and
`invariance_reachability`. Under the coarser reporting taxonomy, this source
pool contains 250 bounded-response, 125 conjunction, and 125 bounded-global
items.

The sampled source pool and the generated candidate pool are different
objects: a source requirement may be used with more than one
natural-language/prompt variant. The 500-formula candidate count reported in
the paper therefore counts generated formulas, not 500 statistically
independent requirements. Of those candidates, 499 are derived from sampled
DeepSTL requirements and one from NASA FRET LPC. Variants derived from the same
source requirement share a `requirement_id` and remain in the same statistical
cluster.

### Initial formulas

GPT-5.6 translates each requirement variant using only its text and signal interface; the reference formula is not included in the model input. Generation uses several prompt variants in which the natural-language requirement is intentionally **underspecified**, mimicking informal engineering requirements. Depending on the variant, the text may leave open:

- whether a condition holds **always** or **eventually**;
- whether a condition is **negated**; or
- whether multiple conditions are connected by **and** or **or**.

These prompt variants produce diverse semantic discrepancies without exposing `φ*` to the model. The generated, unrepaired formula is `φ0`; it is the common starting point of every method, not a competing baseline. GPT-5.6 generated 500 DeepSTL/FRET candidates, 32 ARCH-COMP candidates, and 60 STDP candidates before filtering.

This construction yields a **repair benchmark for informally stated requirements**. It models the practical situation in which a natural-language requirement can be incomplete or ambiguous about a semantic choice, such as temporal modality, negation, or a Boolean connective. In such cases, an LLM-generated formula can be a plausible reading of the text while still differing from the engineer's intended semantics. The labelled traces provide additional semantic evidence that a repair method can use to recover that intent. The benchmark is not intended to estimate the population-level error rate of GPT-5.6 or the natural prevalence of individual fault types in unrestricted NL-to-STL translation; its fault frequencies characterize the selected repair set.

### Freezing for evaluation

Once a candidate enters the repair set, its requirement, formulas, interface, and trace constraints are frozen. `Incorrect_STL.csv` stores `φ0`; `Oracle_STL.csv` stores `φ*`. The same frozen instance is used by ReSTLess, `noloc`, `no_self_coeff`, `no_ceclass`, LLM-CE, and LLM-rewrite.

## Files

| File | Content |
|---|---|
| `<Dataset>/instances.jsonl` | One JSON object per instance (fields below) |
| `<Dataset>/excluded.csv` | Candidates that were generated but **not** kept, with the reason |
| `<Dataset>/excluded_summary.csv` | Number of excluded candidates per reason |

The experiments do not read these files directly. They read the frozen copies in `experiments/frozen/<tag>/instances/<instance_id>/` (`Incorrect_STL.csv`, `Oracle_STL.csv`, `config.json`, `spec.json`), which are derived from `instances.jsonl`; see [Data](../README.md#data) in the main README.

## Instance fields

The three files share the core fields below. ARCH-COMP and STDP use the first name, DeepSTL the second where they differ.

| Field | Meaning |
|---|---|
| `instance_id` | Instance name. Experiment results use `<Dataset>__<id>`, for example `Archcomp__bench_AFC27`, `STDP__stl_005`, and `DeepSTL-0001__gpt-5.6-sol__t0` |
| `requirement_id` | Stable ID of the source-requirement group. Multiple natural-language/prompt variants may have different instance IDs but the same requirement ID; confidence intervals are clustered by this field |
| `faulty_formula` / `phi0` (`stl_incorrect`) | The initial formula φ0 |
| `oracle_formula` / `phi_star` (`stl_ground_truth`) | The reference formula φ\*. Offline it is used to construct the repair set; during a repair run it is hidden from the methods and used only to label traces and perform the final correctness check |
| `english_requirement` / `nl` (`nl_en`) | The natural-language requirement |
| `signal_types`, `signal_bounds`, `boolean_signals`, `discrete_signals`, `derived_signals` | The signal interface: type of each signal, its value range used for trace generation, and boolean, discrete or derived signals |
| `time_start`, `time_end`, `time_step` (`horizon_H`) | Time grid over which traces are generated and formulas are compared |
| `k_gen`, `ceclass_k`, `ceclass_class_limit`, `round_trace_budget` | Trace-generation settings recorded with the instance. The values actually used are frozen in each `spec.json` and `config.json` |
| `faulty_node_count`, `faulty_tree_depth` (`formula_n_nodes`, `formula_depth`) | Size and depth of φ0 |
| `split`, `upstream_method`, `generation_mode` | Bookkeeping: all instances are in the `test` split. The initial formulas of all three datasets were produced by GPT-5.6. `upstream_method` is `gpt-5.6-sol` for DeepSTL; for ARCH-COMP and STDP, the legacy label `curated` records that their English requirement texts were manually written, not that `φ0` was manually constructed. `generation_mode` is the trace-generation mode of the frozen experiments |

DeepSTL instances carry extra fields:

| Field | Meaning |
|---|---|
| `fault_type` | Types of the faults between φ0 and φ\*: `comparator`, `temporal` or `boolean` |
| `fault_location`, `fault_location_source` | Tree paths of the faulty nodes, and how they were found (`tree_diff`) |
| `matched_faults`, `fault_count` | The detected structural differences between φ0 and φ\* (kind, from, to) and their number |
| `repairability_class`, `repair_edit_candidates` | The class of repair needed and the edit operators that can express it |
| `domain`, `complexity`, `deepstl_type` | Requirement domain and shape (`conjunction`, `bounded_global`, `bounded_response`, `other`) |
| `infinite_horizon_cap`, `infinite_horizon_policy` | Formulas keep `inf`; where a formula has an unbounded operator (110 of 123 instances), trace generation and equivalence use a fixed horizon cap of 100; the field is empty for the other 13 |

For `DeepSTL-0123__gpt-5.6-sol__t0`, `source` and `dataset_family` identify the
upstream source as `NASA FRET LPC`, while `dataset` and `benchmark` remain
`DeepSTL` because the submitted paper reports this instance in the DeepSTL
column.

The fault types of the other datasets are determined at analysis time (`restless/evaluation/tables/fault_type_table.py`) and stored in `results/final_145/fault_types.csv`.

## How the repair set was selected

A generated `φ0` enters the repair set only if it parses, matches the signal interface, admits traces for the equivalence query, is not equivalent to `φ*` under the frozen bounded evaluation semantics, and differs from `φ*` only through edits supported by the evaluated repair space. The remaining candidates are recorded in `excluded.csv`.

| Outcome | Meaning | ARCH-COMP | DeepSTL/FRET | STDP |
|---|---|---:|---:|---:|
| Generated candidates | GPT-5.6 translations before filtering | 32 | 500 | 60 |
| `already_correct` | `φ0` is already equivalent to `φ*` under the frozen bounded evaluation semantics; there is nothing to repair | 17 | 300 | 48 |
| `syntax_error_or_no_trace` | `φ0` does not parse, does not match the interface, or admits no traces for the equivalence query | 0 | 57 | 2 |
| `error_outside_the_edit_scope` | The difference requires an unsupported edit, such as changing a threshold or signal name | 3 | 20 | 0 |
| **Repair set** | Semantically wrong and repairable within scope | **12** | **123** | **10** |

The repair edit space keeps signal names and predicate thresholds fixed: ReSTLess edits operators, comparators, temporal operators and bounds, and the structure of the formula (see the main README).

## Oracle separation

The reference formula `φ*` is withheld from formula generation, prompts, diagnostics, and repair. Offline, benchmark construction uses `φ*` to exclude candidates that are already correct or whose discrepancy lies outside the evaluated edit scope. During a repair run, `φ*` is hidden from every method: the oracle uses it only to label queried traces, and the final evaluation uses it to decide correctness by canonicalization followed by a Z3 check of the disagreement formula. LLM-rewrite receives no labelled traces; LLM-CE receives the requirement, interface, current hypothesis, and the labelled traces accumulated by its own run, but never the reference formula itself.

## Scope and reproducibility

This artifact freezes the generated candidates, exclusion outcomes, retained
instances, and downstream experiment configurations. It supports exact
reproduction of the reported evaluation from the frozen formulas and stored
run records. It does not replay the historical API calls that originally
produced `φ0`; consequently, formula generation is documented at the protocol
level, while the retained benchmark and repair experiments use frozen inputs.

All claims of semantic correctness or equivalence in this artifact are
relative to each instance's frozen bounded evaluation semantics: its signal
domains, time grid, finite horizon, and, where applicable, `H_inf = 100`. They
do not claim equivalence over unrestricted signal domains or an unbounded
dense-time semantics.

## Using an instance

```python
import json
rows = [json.loads(l) for l in open("benchmarks/STDP/instances.jsonl")]
r = rows[0]
print(r["instance_id"], r["faulty_formula"], "->", r["oracle_formula"])
```

To repair one instance end to end, use its frozen spec (see [Run the experiments](../README.md#run-the-experiments)):

```sh
RESPSTL_RESULTS_ROOT=.runcheck python3 -m restless.pipeline.run_instance \
  experiments/frozen/restless_stdp_test/instances/STDP__stl_005/spec.json --methods restless
```
